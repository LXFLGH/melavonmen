# 状态路由和阻断门禁

**第一步只读**：列出需求/提示词、代码、Doc、Wiki、索引、测试、项目记忆及用户限定的交付范围；不预设文件命名必须是`doc/`或`wiki/`。复用现存等价结构，迁移前检查受保护内容。

| 状态 | 要做的事 | 开工门禁 |
|---|---|---|
| P：只有提示词 | [需求编译](10-prompt-audit.md)：规范化提示词、识别矛盾/歧义/缺口；询问阻断问题 | 关键问题明确，用户选择只建Doc或Doc后执行 |
| C0：有代码，无Doc/Wiki | 审计源码 → 先建立[Doc](20-doc-schema.md)与索引 → 按需建Wiki | Doc真实可解析、核心合同经验证；**>20,000 LOC**建立Wiki的100%文件索引 |
| D：有Doc/Wiki但无代码 | 先读已有索引、检查冲突与方案，无法从真实源码验证的内容标`unverified` | 仅能写文档或方案，不能伪称已经实现 |
| CD：有代码且有Doc或Wiki | 先读索引/相关模块 → 对比代码/合同 → 修正矛盾和更优方案记录 → 执行 | 阻断问题已处理，Doc目标合同先行，Wiki当前事实保持真实 |
| 部分文档缺失 | 保留已有Doc/Wiki，修复索引，按需补目标合同或实现映射 | 不覆盖未验证事实；只有Doc且源码>20k需补Wiki |
| A：要求生成素材图 | 读[素材交付](65-asset-delivery.md)：先定用途/尺寸/命名/清单，再逐文件生成 | **一素材一文件**（精灵表需 atlas+逐帧源）；交付带清单与`validate_assets`结果 |

**LOC精确定义**：受版本控制的首方源代码及项目自有测试的物理文本行数，含空行/注释；排除vendor、依赖、构建输出、自动生成物、锁文件、资产、Doc/Wiki。记录文件集合、各语言LOC、统计命令、revision；**严格大于20,000才自动建Wiki**（等于20,000不触发）。无权读取源码不得猜测LOC。

**阻断判定**：互相冲突的需求、关键接口兼容、数据所有权、安全或不可逆行为不清晰 → 列出`id/type/evidence/impact/options/question`并向用户提问；答案记录进Doc，不重复问已回答问题。非阻断事项可记录可回滚假设并继续。

**素材类需求的额外判定**：用户要求“生成素材/贴图/图标/立绘”时，交付形态默认是**多文件、一素材一文件**，不需要为“要不要打包”额外提问；**精灵表（sprite sheet）是常规例外**，用户要动画帧表/图块集时直接按[精灵表契约](65-asset-delivery.md)交付（atlas + 逐帧源 + `sprite_sheet` 登记）。除精灵表外的打包（多主题图标集、UI 图集）才需用户明确要求并记录决策。生成原件进`assets/_raw/`，交付物进`assets/<category>/`，不覆盖同名既有素材。

**分阶段Wiki**：创建时文件清单必须索引覆盖100%，受影响源码文件必须有可定位的实现记录和足够深度的审计；不要求开工前把整个大型项目每个函数都注解完。`indexed_sources`与`deep_sources`单独计量并向用户披露。
