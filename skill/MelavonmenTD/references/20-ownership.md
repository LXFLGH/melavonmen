# 20 · 谁建什么（owner 决策）

一个形状只能有一个 owner。判据一句话：

> **改一个数字就要重建的放代码；改一次就定稿的放 Blender。**

## 矩阵

| 特征 | owner | 理由 |
| --- | --- | --- |
| 布尔密集：散热孔阵列、挖槽面板、法兰、齿轮 | `cad` | 参数化 CAD 引擎的 difference/pattern 是声明式的，改参数就重算 |
| 需要 STEP / 壁厚 / 公差的件 | `cad` | 只有实体内核能证明 `closed` / `wall.min_mm` |
| 雕刻、细分曲面、需要烘焙法线/AO 的曲面 | `blend` | 这类几何的表达成本在 three.js 里高一个数量级 |
| 一次性高模、骨骼、形态键 | `blend` | 定稿后不再改 |
| 程序化阵列（101 键帽 → 8 个几何体） | `js` | 参数化复用是代码天然优势 |
| CanvasTexture 丝印 / 键帽字符 | `js` | 纹理要随内容变（换字符、换语言） |
| 片元着色器（CRT、屏幕、玻璃） | `js` | Blender 的 Principled 表达不了 |
| 与交互耦合的部件（按键下压、旋钮转动） | `js` | 需要每帧驱动 |
| 尺寸会联动重生成的整机 | `js` | 见「一体成型」类需求 |

## 三个反模式

1. **同一形状建两遍**（js 里搭一个，Blender 里又搭一个）→ 立刻二选一，另一个删掉。
   如果只是要“对比”，用 `parity` 检查 bbox/tris，不要长期保留两份。
2. **把着色器该干的活交给几何**：用几千个三角形去模拟扫描线、网格、织物。
   → 这些是贴图/着色器的活。
3. **把几何该干的活交给着色器**：用视差贴图假装开孔，结果侧视穿帮。
   → 有厚度、要看侧面的槽一律真几何。

## 交接契约（cad / blend → js）

导出 glTF 时必须满足：

| 项 | 要求 |
| --- | --- |
| 单位 | 米（`export_yup=True`），缩放由 `unit_mm` 换算 |
| 轴向 | +Y up，+Z 朝观察者 |
| 原点 | 零件自身的支撑点（不在地心，不在世界中心） |
| 命名 | 与 `spec.parts[].name` 完全一致，进场景后 `obj.name` 不变 |
| 材质 | 槽名固定：`body` / `dark` / `metal` / `glass`，禁自造 |
| UV | 每个带图零件都有 UV0；贴图 ≤ 2048 |
| 三角数 | ≤ `spec.budgets.tris` 的单件配额 |

`glbcheck.mjs` 校验的就是这张表；任何一项不过，回 Blender 修导出，不要在 three.js 里打补丁。

## 一体成型的判据

外壳、面板、键盘台面这类“看起来是一块模具”的件，**不要**用多个 box 拼。
先问：

- 侧影线是否连续？（断开 = 拼接感）
- 两个件的接缝有没有倒角/过渡，还是 90° 硬接？
- 光打上去，接缝处是否出现一条比周围更亮的细线？（法线不连续）

三条里任意一条不满足，就说明该用放样/扫掠做成一整块，而不是拼。
