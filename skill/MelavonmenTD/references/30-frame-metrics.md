# 30 · 帧级度量

四个数字能覆盖绝大多数“看起来不对”。全部由 `scripts/frame.mjs` 自动量。

## 1. 主体覆盖率 coverage

```
coverage = 屏幕投影面积(主体 bbox) / 视口面积
```

- 目标区间由 `shots[].coverage` 给，常规产品图 `[0.25, 0.55]`。
- `< 0.25` → 主体太小，细节全糊在一起（先怀疑这个，再怀疑材质）。
- `> 0.55` → 边缘被裁，或透视过强导致近端变形。
- **不要凭感觉调机位**：先算覆盖率，再用 `fit.mjs` 的方式反解距离。

反解（透视相机，竖直视角 `fov`）：

```
distance = (halfHeight / tan(fov/2)) / (coverage^0.5) * 画面宽高比修正
```

`shot.mjs --auto` 用的就是这个，把 bbox 对角线当 `halfHeight`。

## 2. texel 密度

```
texel_per_px = 贴图宽(px) / 该表面在屏幕上的宽(px)
```

- 文字类（丝印、键帽字符、标签）**≥ 1.2**；纯色/噪声类 ≥ 0.8 即可。
- `< 1.0` 就是“贴图被压缩”，再好的字体也糊。
- 这条比“提高画布分辨率”更根本：抬画布但不拉近机位，比值不变。

实测例子：终端画布 924 px、屏幕投影 533 px → 1.73（看着还行），
但每个字符只有 6.6 px；把机位拉近到屏幕 639 px、画布 1364 px → 2.13，字符 8.0 px 才清楚。
**字符宽度 = 屏幕宽 / 列数**，这个数低于 7 px 就一定糊。

## 3. 屏幕空间周期（摩尔纹）

对任何固定周期花纹（扫描线、阴罩、网点、编织）：

```
period_px = 屏幕宽度 / (周期数 × (表面屏占比 × 视口宽))
```

- `period_px < 2` 时必然走样，必须用 `fwidth()` 做 LOD 淡出，不能靠调幅度。
- 判据写成断言：`period_px < 2 → 必须有 fade`，否则 `E_PERIOD_MOIRE`。
- 实测例子：阴罩 1 texel 周期在屏上只有 1.73 px，整屏变成噪点；上 `fwidth` 淡出后干净。

## 4. 预算

| 指标 | 桌面 | 移动 | 说明 |
| --- | --- | --- | --- |
| draw calls | ≤ 250 | ≤ 80 | 每个 unique(geometry, material) 一次 |
| triangles | ≤ 150k | ≤ 50k | 主体 + 环境 |
| 唯一材质 | ≤ 40（可用 `--budget mats=N` 覆盖） | ≤ 20 | 超出说明该合并；**逐键字符贴图**这类一物一材质的设计要用 `mats` 放宽，否则会误报 degraded |
| 几何复用率 | ≥ 3 | ≥ 3 | 实例数 / 几何体数，键帽这类应 ≥ 10 |
| 贴图显存 | ≤ 64 MB | ≤ 24 MB | 按 4 通道 8bit 估 |

`budget.mjs`（内联在 `frame.mjs`）输出这五项并给合并建议：
按 `geometry.uuid` 分组，列出“数量 ≥ 5 且材质相同”的组，就是可 InstancedMesh 的候选。

## 确定性

两张图能比，前提是同一个 `build`：

```json
"build": { "spec_hash": "sha256:…", "t": 0, "dpr": 1, "freeze": true }
```

页面需要提供 `?freeze=1`：固定 `uTime`、停阻尼、固定 devicePixelRatio。
做不到就别做像素 diff，只比度量数字。
